# 002 — 스펙 001 적대적 검토 결과와 반영

> 2026-07-24. opus 서브에이전트 적대 검토. 전 항목 스펙 v2에 반영(§6 룰 판정 계약 신설).
> 교훈: **거버넌스 게이트 스펙은 "룰 목록"이 아니라 "판정 계약(fail-closed 불변식)"이 본체다.**
> 룰을 한 줄 산문으로 두면 OR/서브쿼리/alias/Raw 처리가 구현자의 동전 던지기가 되고, 그 절반은 우회 가능으로 떨어진다.

## CRITICAL 9건 (게이트 우회 또는 흔한 쿼리 오차단)

| ID | 공격 | 반영 |
|---|---|---|
| C1 | `consent_yn='Y' OR 1=1` — OR 가지 매치를 충족으로 인정하면 무력화 | §6.1 최상위 AND conjunct만 인정 |
| C2 | 서브쿼리/CTE/파생 테이블에 거버넌스 테이블 은닉 → 룰 미실행 | §5.2 재귀 IR + §6.2 전 스코프 실행 |
| C3 | UNION 한 팔만 위반 → 깨끗한 팔이 세탁 | §5.3 팔별 독립 스코프, any-arm 위반 |
| C4 | `SELECT 1; DELETE ...` 멀티 스테이트먼트 스태킹 | §5.1 문 2개 이상 hard-fail |
| C5 | `DELETE FROM user_events` 무제한 변이가 룰셋 사각 | §2 SELECT만 저장 가능(변이 거버넌스는 다음 단위) |
| C6 | `COUNT(*)`·`EXISTS(SELECT *)` 오차단 | §6.7 select-item star만 발화, EXISTS 면제 |
| C7 | alias 미해석 → 다른 테이블 컬럼으로 파티션 룰 오판(양방향) | §5.2 ResolvedColumn + §6.4 귀속 불가=미충족 |
| C8 | Raw escape hatch의 기본값 미정 → fail-open이면 우회 통로 | §6.3 Raw는 절대 미충족, 검증 불가=차단 |
| C9 | 자유 텍스트 purpose = 오타/의도적 라벨 변경으로 BLOCK 자가 면제 | §5.4 관리형 purpose 목록 (결정 번복) |

## HIGH 6건

- H1 술어 매치 문자열 비교 취약 → §6.5 구조 비교 + 닫힌 동치 목록(`=` 순서, 케이스, `IN('Y')≡='Y'`)
- H2 OUTER JOIN ON은 행 필터가 아님 → §6.1 INNER ON만 WHERE 동치, OUTER ON 미충족
- H3 `DATE(col)=...`는 파티션 프루닝 무산 → §6.6 베어 컬럼 `=`/`IN`/`BETWEEN`만 충족
- H4 부정형(`NOT`, `<>`) → §6.1+§6.5로 미충족 명시
- H5 파서 DoS(크기·중첩·타임아웃) → §5.1 64KB/타임아웃 2s/위반 응답
- H6 검증 체크리스트가 "돈다"만 증명 → §12 우회 스위트+오탐 스위트로 재작성

## MEDIUM/LOW 요지

존재 기반 검사의 선택도 한계 문서화(M1), lint 스냅샷·relint 백로그(M2), 쿼리 수정/삭제 API 추가(M3),
구조 비교 강제·주석 삽입 테스트(M4), Druid 의존성 격리(버전 고정+ArchUnit, DataSource 연결 금지)(M5),
201 body에 LintReport(M6), dialect 필수 검증(L1), LIMIT 0/거대값 한계 명시(L2), 카탈로그 방언 컬럼 부재는 PG 전 재검토(L3).

## 재사용 가능한 체크리스트 (다음 룰/방언 추가 시)

새 룰이나 방언을 추가할 때 이 9개 축으로 자문할 것:
OR 가지 / 스코프 은닉 / UNION 팔 / 멀티 스테이트먼트 / 문 종류 사각 / 오탐(관용구) / alias 귀속 / escape hatch 기본값 / 사용자 통제 입력에 의한 룰 적용 조건.
