## 핵심 발명: 2계층 어휘 통제

**컬럼 클래스별 제약 사전 → 컬럼 매핑 → 규칙은 매핑된 제약만 참조.**
관리형 purpose 철학(사용자 임의 입력으로 룰 적용을 좌우 못 함)의 일반화. 반영 1순위 근거.

## 화면 7종 (4그룹)

탐색: 데이터베이스(3단 탐색기, 인덱스·파티션·PII·제약 매핑 표시) / 쿼리: 에디터(실행·AI 에이전트·하단 3탭), 저장된 쿼리(승인 상태·규칙 검사 컬럼) / 거버넌스: 승인 요청(요청서+순차 승인 라인), 규칙 관리(3단: 목록·빌더·미리보기/IR 트리), 제약 카탈로그(제약 정의+컬럼 매핑) / 관리: 접근 권한(사용자별 DB·테이블 allow).

## 정책 메타모델

- **제약 정의**: 컬럼 클래스 6종(pii/boolean/datetime/numeric/key/string, 자동 판별 규칙 내장) × kind 5종:
  mask(SELECT 치환)/filter(WHERE 주입)/block(참조 시 거부)/join(필수 조인 검사)/integrity(무결성 술어).
  강제식 문법: `{col}` 치환자 + `:param` 파라미터. **PARTITION_KEY kind 없음**(§모호 3).
- **규칙**: {name, scope(single/multi/global), server 귀속(서버 간 조인 미지원 명시), severity(error=차단/warning=경고),
  AND/OR 중첩 트리(기본 모드=평면 AND, OR=어드밴스드)}. 조건 op 5종: requires/joins/must_be_within/must_be_masked/blocks.
  조건 값 = 해당 컬럼에 매핑된 제약만 선택 가능. 빈 그룹 → 저장 disabled(fail-closed UX). 규칙별 위반 횟수 집계.
- **승인**: 쿼리 작성 요청서(목적 + 대상 테이블 + 적용 규칙 선택 + 비즈니스 요건 체크리스트 5종 + 순차 승인 라인) →
  상태 5종(draft/pending/approved/rejected/cancelled). 승인 요건이 규칙 판정의 입력이 됨(REQ 연계).
- **실행·마스킹**: 실행 버튼 + 마스킹된 결과(`j***@naver.com`) + "LIMIT 100 적용됨" → 쿼리 재작성 엔진 시사.
- **기타**: 서버(클러스터) 레지스트리, 멀티 벤더(MySQL/PG/Trino), PII 플래그, AI 에이전트(NL→SQL), 자동 저장.

## Gap 요약 (규모)

행위: B1 제약 메타모델(L) · B2 규칙 데이터화(L) · B3 승인(L) · B4 권한(L) · B5 실행(L) · B6 재작성(L) ·
B7 서버 레지스트리(M) · B8 멀티 벤더(L) · B9 PII(S) · B10 쿼리 상태 필드(M) · B11 위반 통계(S) ·
B12 AI(L) · B13 LIMIT≤1000(S) · B14 테이블 메타(M).
UI: 셸 개편(M) · DB 탐색기(M) · 에디터 재구성(M) · 목록 강화(S–M) · 카탈로그 개편(M, B1 종속) · 규칙 빌더(L, B2 종속).

## 사람 결정 필요 (상위)

1. **판정 vs 재작성**: mask/filter가 "미충족 차단"인지 "자동 주입/치환"인지 — B1·B5·B6 규모를 가른다.
2. **severity 충돌**: 디자인 r3은 전역 경고 규칙에 SELECT * 차단 포함 — 현행 no-select-star는 BLOCK. 규칙 단위 severity로는 못 담음 → 조건 단위 severity 필요 여부.
3. **파티션 키 룰 행방**: 신모델에 kind 없음 — kind 추가 vs filter로 흡수 vs 인덱스 메타에서 유도.
4. **요청자의 규칙 선택**: BLOCK 규칙을 빼고 제출 가능하게 보임 — 적대 검토 C9(자가 면제 금지)와 정면 충돌. 전역·BLOCK 상시 강제 여부.
5. 승인 게이트 위치(작성 전 vs 저장 후), 승인 라인 편성 권한, purpose→비즈니스 요건 이관, :param 결정 시점,
   실행 인프라(자격 증명·감사), 열람 전용 범위, 위반 집계 기준, 자동 저장 vs fail-closed, §6 계약 유지(디자인 무언급 — 폐기 아님 가정).

## 반영 순서 제안 (합의 대상)

1순위 제약 메타모델+카탈로그 개편 → 2순위 규칙 데이터화(AND 트리 축소판, 기존 §6 테스트 회귀 유지) →
3순위 쿼리 상태·목록 UX → 4순위 승인 워크플로 → 5순위 권한+셸·탐색기+서버 레지스트리 →
후순위 실행·마스킹 재작성 / 멀티 벤더 / AI (각각 독립 스펙).
