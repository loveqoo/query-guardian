# 007 — 디자인 UI 전면 컨버팅 실행에서 배운 것

> 2026-07-25. spec 003 실행(7화면 antd 컨버팅). 병렬 위임 7 + 기반 1 + 검토 1.

## 무엇이 컨버팅을 쉽게 만들었나

1. **디자인 원본이 이미 antd 앱이었다** — dc.html은 `x-import ... AntDesignSystem.*` + 내장 x-dc 스크립트(state·헬퍼).
   즉 "화면을 상상"하는 게 아니라 데이터·템플릿을 antd JSX로 옮기는 기계적 작업. 원본이 컴포넌트 기반이면
   컨버팅 난이도가 급감한다. **원본을 먼저 통독해 이 사실을 파악한 것**이 위임 정확도를 만들었다.
2. **기반(테마·목데이터·셸)을 먼저 직렬로 확정하고 화면을 병렬화** — 검토가 제안한 분할. 7화면이
   공유 자산을 읽기만 하므로 통합 충돌 0. 최종 통합 빌드가 한 번에 초록.
3. **위임 브리프에 원본 라인 좌표 + 토큰 표를 박은 것**(learning 006 반영) — 7개 에이전트가 재질문 없이
   충실 재현. 요약본 대신 "dc.html line X–Y 직참조"를 강제한 게 핵심.

## 마찰·교훈

1. **내 위임 브리프의 실수가 그대로 산출물에 박힌다** — M1 브리프에서 pending 상태색을 blue로 잘못 지시했고
   (디자인은 gold), 두 화면 에이전트가 그대로 따랐다. 검토 리포트가 gold라고 명시했는데도 브리프 작성 시
   놓쳤다. → **브리프의 토큰 값은 검토 리포트와 교차 검증 후 확정**. 공유 상수(테마)의 오류는 전 화면에 전파된다.
2. **디자인에 없는 컴포넌트(@ant-design/x)** — 에디터 AI 패널이 쓰던 것. 에이전트가 순정 antd로 재구성.
   신규 의존성 추가보다 기존 스택으로 근사하는 게 옳은 기본값(번들·유지보수).
3. **스텁 폴백이 실제로 동작** — 저장된 쿼리가 비면 예시 데이터를 "예시" 태그로 표시하고 실 데이터가
   생기면 대체. 스텁 규약(§4-2 조용한 무시 금지, 예시 라벨)이 화면에서 검증됨.
4. **실 게이트 무변경 원칙이 지켜짐** — 컨버팅 후에도 ssn 차단·정상 통과·저장 422가 그대로. 벤더/연결
   select disabled로 non-MySQL이 게이트에 못 들어감. UI 전면 교체와 게이트 불변을 동시 달성.

## 재사용 체크리스트 (다음 디자인 컨버팅 시)

원본이 컴포넌트 기반인지 먼저 확인 → 기반(테마·목·셸) 직렬 확정 → 토큰 값을 검토와 교차검증 →
화면 병렬 위임(원본 좌표+토큰 인용) → 통합 빌드 → 화면별 스크린샷 대조 → 공유 상수 오류만 배치 수정.
