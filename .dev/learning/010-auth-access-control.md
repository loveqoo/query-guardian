# 010 — 인증·접근 권한(spec 007) 구현에서 배운 것

> 2026-07-25. actor 스텁 → 세션 principal 승격 + 데이터 권한 게이트.

1. **"권한을 도입하는 작업"이 판정을 약화시킬 수 있다(C4)** — spec 005의 C1(게이트 추가가 게이트를 여는 역설)과
   같은 계열. 권한 필터를 판정 카탈로그에 넣으면 권한 없는 사용자에게 `partitionKeys=[]`·`blockedColumns=∅`가
   되어 **권한이 없을수록 룰을 덜 받는 역전**이 생긴다. 스펙 §6.4 불변식 + **ArchUnit 규칙**으로 고정
   (`rules`·`lint`·`ir`는 `auth`에 의존 금지 — Druid 격리와 같은 방식). 문장만 두면 다음 리팩터가 되돌린다.

2. **풀을 합치면 우연히 닫혀 있던 구멍이 열린다(C1)** — 요청자 풀(u*)과 승인자 풀(ap*)이 분리돼 있어
   "자가 승인"이 **구조적으로 불가능**했다. `app_user` 하나로 통합하는 순간 STEWARD가 자기 요청을 자기가
   승인할 수 있게 된다. 리팩터가 제거하는 것은 코드만이 아니라 **암묵적 불변식**이다 —
   합치기 전에 "분리 덕분에 성립하던 성질"을 열거할 것.

3. **`changeSessionId()`는 세션이 없으면 던진다** — 내가 넣은 세션 고정 방어가 **모든 첫 로그인을 500**으로
   만들었다(브라우저·시드 포함). 위임 에이전트가 프로덕션 버그로 정확히 보고했고, 프로덕션을 고치지 않고
   멈춘 판단이 옳았다. 교훈: 보안 하드닝 API는 **전제 조건**(세션 존재 등)을 확인하고 쓸 것.
   그리고 **위임 브리프에 "프로덕션 버그로 보이면 고치지 말고 보고"를 넣은 것이 이 발견을 만들었다.**

4. **HTTP 헤더 ASCII 제약이 설계를 개선한 두 번째 사례** — spec 005에서 actor를 id로 바꾼 덕분에
   `app_user.id`로 그대로 승계돼 마이그레이션이 단순했다(이름 기반이었으면 전면 개편).

5. **역할(기능 축)과 권한(데이터 축)을 분리한 게 유효했다** — ADMIN도 데이터 권한을 우회하지 않으므로
   "관리자니까 다 보인다"는 함정이 없다. 대신 ADMIN이 자기 권한을 올릴 수 있어(자기상향) 감사 이벤트 +
   자기 권한 편집 금지를 스펙에 넣었다(M3에서 구현).

6. **테스트 헬퍼 시그니처 유지가 이관 비용을 지웠다** — `postAs(path, actor, body)`를 그대로 두고 내부만
   헤더→쿠키로 바꿔, 호출 지점 100여 곳을 손대지 않았다. 인증 도입처럼 전역 변경일수록
   **경계 함수 하나로 흡수**하는 설계가 값지다.
