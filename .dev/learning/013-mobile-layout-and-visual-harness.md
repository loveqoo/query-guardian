# 013 — 모바일 대응과 시각 회귀 하네스에서 배운 것 (spec 009)

## 1. 사용자가 보는 것과 지표가 어긋나면, 고칠 것은 **지표**다

이 작업에서 두 번 겪었다.

**첫 번째**: 가로 넘침을 `documentElement.scrollWidth > clientWidth`로 재니 7개 화면이 **전부 통과**했다.
셸에 `overflow: hidden`이 걸려 있어 내용이 **잘려서** 문서가 넓어지지 않았기 때문이다 — 스크롤바보다 나쁜 상태
(사용자는 잘린 것을 볼 방법이 없다)가 지표를 통과했다. 정의를 "뷰포트를 넘는 요소는 **의도된 가로 스크롤 영역**
안에서만 허용"으로 바꾸자 7개 전부 실패로 뒤집혔고, 그때부터 진짜 수정이 시작됐다.

**두 번째**: 폭 지표를 통과한 뒤 "완료"라고 보고했는데, 사용자가 실기기에서 "컬럼이 보이지 않는다"고 지적했다.
원인은 **높이**였다 — 컬럼 표 컨테이너가 높이 79px에 내용 861px. 폭만 재는 지표는 이걸 볼 수 없었다.

교훈: 지표를 만들었다는 사실이 검증을 대신하지 못한다. **지표가 사용자 증상을 재현하는지**를 먼저 확인해야 한다.
쉬운 검사법: 고치기 전에 지표를 돌려 **실패해야 할 것이 실패하는지** 본다. 처음부터 전부 통과하면 지표가 틀린 것이다.

## 2. `fullPage` 스크린샷은 **내부 스크롤러**를 담지 못한다

앱 셸이 `100dvh` + `main` 내부 스크롤 구조라, Playwright `fullPage: true`가 화면 **아래쪽을 담지 않는다**
(문서 높이 = 뷰포트 높이). 결함이 정확히 그 사각(첫 화면 밖)에 있었고, 나는 "스크린샷을 봤다"고 믿었다.

대응: 긴 뷰포트 프로젝트(390×2000)를 추가해 아래쪽까지 스냅샷에 넣는다. 검증용 스크린샷을 찍을 때는
**문서가 스크롤되는 구조인지 컨테이너가 스크롤되는 구조인지**를 먼저 확인해야 한다.

## 3. 전역 "안전망" CSS는 조작 요소를 부순다

`min-width: 0`을 flex 자식 전체에 걸었더니 **버튼이 폭 2px**이 됐다. 넘침은 사라지고 누를 수 없는 버튼이 생겼다.
컨테이너는 줄어들어야 하고 **조작 요소는 줄어들면 안 된다** — 두 부류를 구분하지 않은 규칙은 한쪽을 망친다.
지금은 버튼·태그를 축소 대상에서 빼고 `flex-shrink: 0`을 준다. 대신 행을 줄바꿈시킨다.

## 4. 브레이크포인트의 기준은 뷰포트 폭이 아니라 **남는 내용 폭**

768px(antd `md`)로 잡았더니 태블릿 3화면이 실패했다 — 768px에서도 사이드바 236px를 빼면 내용이 **532px**뿐이라
`300px 300px 1fr` 그리드가 그대로 넘쳤다. 992px(`lg`)로 올려 해결. 고정 사이드바가 있는 레이아웃에서는
"화면이 좁다"가 아니라 "**콘텐츠 영역이 좁다**"로 계산해야 한다.

## 5. `1fr`은 0으로 줄지 않는다 (그래서 형제를 밀어낸다)

`grid-template-columns: 1fr 1fr`이 좁은 화면에서 "한쪽 2px + 반대쪽 넘침"으로 깨졌다. `1fr`의 최소 크기는
`min-content`이므로, 넓은 형제가 다른 열을 밀어내고 자기가 컨테이너를 넘어간다. 해법은 `minmax(0, 1fr)`이거나
좁은 화면에서 한 열로 접는 것이다. 이 함정은 인라인 스타일로 열을 지정한 모든 그리드에 있었다.

## 6. 데이터 표는 접지 않는다 — **가로 스크롤로 격리**한다

전역 규칙으로 그리드를 한 열로 접었더니 DB 컬럼 표가 "컬럼/타입/클래스/개인정보" 세로 라벨로 뭉개졌다.
값과 컬럼의 대응이 사라지므로 표는 접으면 안 된다. `data-scroll-x` 표시 + 최소 폭으로 격리했고,
그 표시가 측정 허용목록의 기준이 되어 **의도와 검증이 같은 것을 가리킨다**.

## 7. "불변"을 약속했으면 그것을 증명하는 장치를 같이 만든다

"데스크톱 픽셀 불변"은 코드 diff로 증명할 수 없다 — 전역 CSS 한 줄이 전 화면을 바꾼다. 스냅샷 프로젝트를
1280px로 두고 **갱신 없이 통과**하는 것을 증거로 삼았다. 모바일 작업 중 다섯 번 이상 되돌아가 확인했고,
그 덕분에 `minWidth: 460`처럼 미디어 쿼리 밖에 넣은 변경이 데스크톱에 영향을 주는지 즉시 알 수 있었다.
