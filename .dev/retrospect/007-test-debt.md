# 007 — 테스트 부채 상환 회고

> 2026-07-25. 사용자 지시 순서 ①. 기능 추가 전 부채 정리.

## 무엇을 했나
retrospect 005/006이 남긴 미검증 경로 6종을 spec 006으로 묶어 통합 테스트 7건 작성.
전체 102건 통과, **프로덕션 코드 변경 0**.

## 배운 것
- **부채 상환이 곧 검증**: 코드가 맞는지 몰랐던 상태에서 "맞다"로 바뀌었다. 특히 동시 승인(T4)은
  실제 스레드 2개로 경합시켜 @Version 잠금이 단계 건너뛰기를 막는 것을 실증 — 리뷰 리포트의
  주장이 코드에서 참임을 처음 확인했다.
- **dangling 경로는 API 가드를 우회하는 쪽으로 테스트해야 한다** — 매핑 삭제는 409로 막히므로
  dangling이 안 생긴다. 실제로 생기는 경로(컬럼 삭제 → 매핑 연쇄 삭제)를 찾아야 의미 있는 테스트가 됐다.
  "가드가 있으니 안전"이 아니라 "가드를 우회하는 경로가 무엇인가"를 묻는 게 핵심.
- 시스템 룰과 사용자 규칙의 dangling 반응이 다르다(전자는 요구 소멸, 후자는 fail-closed 차단).
  의도된 설계지만 문서화하지 않았으면 나중에 버그로 오인했을 것 — spec 006 §4에 기록.
