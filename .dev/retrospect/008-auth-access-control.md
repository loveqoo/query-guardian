# 008 — spec 007(인증·접근 권한) 회고

> 2026-07-25. 사용자 지시 순서 ②.

## 무엇을 했나
결정 3건(세션 로그인·전 경로 강제·역할 3종) → 스펙 초안 → 적대 검토(fail-open 3종 + 구현 불가 권한 키) →
v2 → M1(인증·엔티티·actor 400·테스트 전환) → M2(권한 게이트·ArchUnit) → M3(사용자/권한 API + 프론트 전면) →
E2E·화면 검증. 102 테스트 통과.

## 잘 된 것
- **spec 005가 남긴 "actor는 접근 통제가 아니다"를 실제 통제로 승격** — 예고했던 교체 지점(X-QG-Actor → 400)이
  그대로 이행됐다. 스펙에 "인증 도입 시 이렇게 바꾼다"를 미리 적어둔 것이 이번 작업을 단순하게 만들었다.
- **판정 경로 무권한 불변식을 ArchUnit으로 고정** — 문장만으로는 다음 리팩터가 되돌린다. 권한이 판정에 새면
  "권한이 없을수록 룰을 덜 받는" 역전이 생기는데, 이제 구조적으로 불가능하다.
- 위임 브리프의 "프로덕션 버그로 보이면 고치지 말고 보고" 조항이 **내 버그**(changeSessionId 첫 로그인 500)를
  잡아냈다. 에이전트가 프로덕션을 건드리지 않고 멈춘 판단이 옳았다.

## 어긋난 것
- 세션 고정 방어를 넣으면서 **API 전제 조건을 확인하지 않았다**. 보안 코드일수록 전제를 읽자.
- 스펙에 테스트 수를 굳은 숫자(109)로 적었는데 실측은 102였다. **숫자는 실측 후 적거나 적지 말 것** —
  다음 스펙이 그대로 복사한다(적대 검토도 이를 지적).
- 프론트 위임이 컨텍스트를 크게 썼다(30만 토큰). 화면 7종 규모의 위임은 화면별로 쪼개는 게 나았다.
