# git 훅 — 감시자를 사람 손에서 떼어낸다 (spec 014 L0-d)

이 저장소의 안전망 상당수는 컴파일러가 표현할 수 없는 성질이라 **테스트로만 발화한다** —
계층 경계(ArchUnit) · 게이트 접근 · 발급 권한 폐쇄 · 감사 코드 전수 · 우회/오탐 스위트 ·
서버 DTO ↔ 화면 스키마 대조. 지금까지 이것들은 *누군가 테스트를 돌릴 때만* 울렸고,
그 누군가는 대개 방금 규칙을 어긴 사람이었다.

## 왜 GitHub Actions가 아닌가

처음에는 워크플로를 만들었다가 **접었다.** 이유 셋:

1. **문제가 로컬에 있다.** 고치려던 것은 "커밋 전에 테스트를 안 돌린다"이고, 그건 이 기계에서
   일어난다. git이 이미 답을 갖고 있는데 외부 서비스를 부를 이유가 없었다.
2. **로컬이 더 많이 덮는다.** 시각 회귀 기준선은 이 기계(macOS)에서 만들어졌고 허용 오차가 0이라
   리눅스 러너에서는 **전부 실패한다.** E2E도 백엔드·DB가 떠 있어야 한다.
   GitHub로 가면 오히려 덮을 수 있는 것을 못 덮는다.
3. **권한을 요구한다.** 워크플로 파일을 쓰려면 토큰에 `workflow` 스코프가 필요하다 —
   GitHub는 파일 *내용*이 아니라 *종류*를 보기 때문이다(그 폴더의 파일은 GitHub가 실행한다).
   테스트만 돌리는 파일 하나 때문에 코드 실행 권한을 여는 것은 값이 안 맞았다.

**GitHub가 필요해지는 시점은 분명하다**: 두 번째 사람이 이 저장소를 만질 때(남의 기계엔 이 훅이 없다),
우회를 막아야 할 때(`--no-verify`), PR에 통과 여부를 붙여야 할 때. 지금은 셋 다 아니다.

## 켜는 법

```bash
git config core.hooksPath .githooks
```

훅이 저장소 안에 있으므로 **버전 관리된다** — `.git/hooks/`에 두면 사본이 각자 낡는다.
클론한 뒤 위 한 줄을 실행해야 켜진다(git은 이것을 자동으로 안 한다 — 그게 보안 설계다).

## 무엇이 언제 도는가

속도가 다르면 자리도 달라야 한다. **느린 훅은 결국 우회당하고, 우회당한 훅은 없는 훅이다.**

| 훅 | 검사 | 실측 |
|---|---|---|
| `pre-commit` | 와이어 대조 · 프론트 타입 체크 · 계약 테스트 | **약 2초** |
| `pre-push` | 위 전부 + 백엔드 테스트 300건 | **약 2분** |

백엔드 테스트를 커밋마다 돌리면 2분이 매번 붙어 훅을 끄게 된다. 푸시는 훨씬 드무므로 거기가 맞다.

## 훅이 덮지 않는 것

- **시각 회귀**(`npm run test:visual`) — 프론트 개발 서버가 떠 있어야 한다.
  훅에 넣으면 서버가 안 떠 있을 때 **엉뚱한 이유로 실패**하고, 그런 훅은 꺼진다.
  화면을 건드렸으면 `pre-push`가 알려 준다 — 그때 손으로 돌린다.
- **E2E**(`execution.spec.ts`) — 백엔드 8080 + 설정 DB + 데모 스키마가 필요하다. 같은 이유.

즉 **"훅이 초록이면 안전하다"는 아직 참이 아니다.** 이 파일이 그 사실을 들고 있는다.

## 급할 때

`git commit --no-verify` / `git push --no-verify`로 건너뛴다. 막지 않는다 —
**막으면 사람들이 훅 자체를 끈다.** 다만 건너뛴 것은 건너뛴 것이고, 다음 푸시에서 걸린다.
