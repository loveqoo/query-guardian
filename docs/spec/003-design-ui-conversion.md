# 003 — 디자인 UI 전면 컨버팅 (antd)

> 상태: **초안 (인간 검토 대기)**
> 작성: 2026-07-25 · 원본: `docs/design/query-guardian-design/Query Guardian.dc.html` (유일한 UI 기준)
> 배경: learning 006 — 부분 충실도는 충실도가 아니다. **수용 기준 = 화면이 디자인과 같아 보이는 것.**

## 1. 목표·원칙

기존 프론트 UI를 **전부 제거**하고, 사용자 디자인(dc.html)을 antd로 충실 컨버팅한다.
- **dc.html이 유일한 UI 원본** — 스크린샷은 보조(파일명·iteration 편차 있음, learning 004).
- 레이아웃·라벨·색·카피를 디자인 그대로. antd 컴포넌트로 대체하되 시각 결과 우선.
- 로직 없는 화면은 **디자인 내장 샘플 데이터로 스텁**(사용자 확정) — 화면부터 일치시키고,
  후속 스펙에서 화면별로 실 로직 교체(순서 유지: 규칙 데이터화 → 쿼리 상태 → 승인 → 권한 → 실행·AI).
- **백엔드는 이번 스펙에서 무변경** — 게이트·룰·카탈로그 API는 그대로 두고 UI가 소비.

### 화면별 요점 (dc.html 라인 좌표는 `.dev/design-conversion-reference.md` — 위임 브리프는 원본 직참조 필수, learning 006)

- **쿼리 에디터**(240–366): 툴바(이름·벤더 select·연결 select·추천/규칙 검사/실행/AI 버튼), macOS 코드창
  (신호등 3점 + `{이름}.sql` + 벤더 버전 라벨 "MySQL 8.0"), 추천 팝업(F/C/ƒ/K 배지), 하단 3탭 —
  규칙 검사 결과(통과 green·경고 gold·오류 red 카드), 실행 결과(마스킹 그리드 `j***@naver.com` + "예시 데이터" 라벨), 메시지.
  AI 패널(360px, 고정 응답 + 프롬프트 3칩 + 다크 SQL 블록). CodeMirror 유지.
  **실 로직 접합 규칙(§8-1)**: (a) purposeCode는 유지하되 디자인에 목적 select가 없으므로 **컴팩트 "목적" select를 툴바에
  추가**(spec 004에서 비즈니스 요건으로 이관 예정, 잠정), (b) 실제 lint는 타이핑 500ms 자동 + "규칙 검사" 버튼도 즉시 호출,
  (c) **실 lint 위반 표시가 우선** — 디자인의 명명된 "통과 3건" 카드는 실 리포트가 없을 때만 노출하거나 "예시"로 명확히 구분,
  (d) 벤더+**연결** select 모두 MySQL/prod-main 외 disabled(§4-4), (e) 실행·AI·마스킹 결과는 스텁 라벨.
- **저장된 쿼리**(370–415): 필터바 5개 + 8열 테이블(이름/벤더/DB/작성자/승인상태/규칙검사/수정일/액션 보기·수정·복제) +
  페이저 + **상세 모달**(803–830, 메타 2×2 + SQL 하이라이트 + "에디터에서 열기"). 승인상태·규칙검사 컬럼은 스텁 값.
- **데이터베이스**(79–237): 3단(연결→테이블→컬럼 상세). 컬럼 상세 하단 **4-섹션 아코디언(인덱스·코멘트·개인정보 컬럼·쿼리 제약)** +
  메타 칩(엔진/인코딩/로우) + 열람전용 배너. prod-main만 카탈로그 실 데이터(B), 나머지·잠금은 샘플.
- **규칙 관리**(558–639, **최대 미명세 — 화면 절반**): 3단(목록 280·빌더·IR 320). 빌더 = 규칙명·severity, 적용 범위·대상 서버(메타·서버간 조인 미지원 안내),
  **기본↔어드밴스드 토글**(기본=평면 AND, 어드밴스드=AND/OR 중첩 rail), **조건 인라인 편집 폼**(op/DB/테이블/컬럼/제약 select,
  **매핑된 제약만 선택** + 미매핑 경고 "제약 카탈로그 → 컬럼 매핑에서 등록하세요"), 저장 disabled 검증("조건이 하나도 없는 그룹이 있습니다").
  우측 IR 2탭: 규칙 설정(요약 문장 + "위반 시 차단/경고합니다") / 규칙 트리(다크 `#0b1220` JSON 뷰어).
- **승인 요청**(418–555): 2탭. 목록(REQ 카드 + pending 액션) + 새 요청 폼(목적·테이블카드 규칙 펼침·비즈니스 요건 5종·**순차 승인 라인** step 배지·화살표·승인자 풀 4인). 승인/반려/제출 버튼은 스텁 메시지(§4-2).
- **제약 카탈로그**(690–800): spec 002의 2탭 실 CRUD를 디자인 섹션 스타일로 이식 + 정의/매핑 모달(756/779). PARTITION kind 처리 §8-2.
- **접근 권한**(642–687): 2단(사용자 4인 목록 + DB 스위치/테이블 체크박스). perms 로컬 토글.

## 4. 스텁 규약 (정책)

1. 스텁 데이터는 **dc.html 내장 샘플 그대로**(REQ-1043, prod-main/analytics-dw/data-lake, 규칙 3종 등).
2. 스텁 액션은 조용히 무시하지 않는다 — antd message로 **"후속 스펙에서 구현 예정"** 명시.
   **적용 대상 명시**: 실행 버튼, 승인 요청 제출, **승인/반려 버튼(디자인엔 핸들러 없음 — 반드시 메시지 부착)**,
   AI 전송·에디터 적용, bell/question 아이콘. 실행 결과·마스킹 그리드에는 **"예시 데이터" 라벨**.
3. 스텁·실 데이터의 경계는 `src/mock/` 모듈로 격리 — 후속 스펙에서 화면별 교체가 국소 변경이 되게.
4. **벤더 select + 연결(connection) select 모두** 디자인대로 3종 표시하되 **MySQL/prod-main 외에는 disabled + 툴팁**.
   (백엔드는 dialect=MYSQL 고정·400 반환. 연결 select도 벤더와 동일 처리 — 적대 검토 갭 보강.)
5. 스텁 필드(승인 상태·규칙검사 컬럼 등)는 UI 표기용일 뿐 게이트 판정에 영향을 주지 않는다.
6. **게이트 불변 (강조)**: 실 게이트 = `createQuery/updateQuery`의 422 차단 + 서버 lint. **어떤 스텁도 이 경로를
   우회·무력화·오인시키지 않는다.** 특히 (a) non-MySQL SQL이 실 저장에 못 들어가게 벤더/연결 disabled를 이행하고,
   (b) 에디터의 스텁 "통과 카드"가 실 lint의 BLOCK/WARN 표시를 가리지 않게 실 리포트를 우선한다.

## 5. 구현 방식

- 기존 `frontend/src/pages/*`·`App.tsx` 전면 교체. `api/client.ts`는 유지(실 로직 화면이 사용).
- 컨버팅은 화면 단위로 서브에이전트 분할 위임 — 각 브리프에 **dc.html 원본 경로 + 해당 화면 섹션 추출 지시** 포함
  (요약본이 아니라 원본 대조, learning 006).
- 라우팅: `/databases /editor /queries /approvals /rules /catalog /admin`.

## 8. 접합·격차 결정 (적대 검토 반영, AI 판단 — 사용자 확인 대상)

1. **에디터 목적(purpose)**: 디자인 에디터엔 목적 select가 없다. 그러나 실 로직의 대표 시나리오(마케팅 동의 FILTER)는
   purposeCode가 있어야 발화한다. → 이번 단계는 **컴팩트 "목적" select를 툴바에 잠정 추가**(디자인에서 소폭 이탈).
   디자인의 정식 답은 승인 요청서의 "비즈니스 요건 체크리스트"이므로, **spec 004(승인 워크플로)에서 purpose를 요건으로 이관**하고
   에디터 목적 select는 제거한다. *(이 이탈이 마음에 걸리면 사용자가 대안 지시 가능.)*
2. **PARTITION kind 격차**: 디자인 kind는 5종(mask/filter/block/join/integrity), 백엔드는 6종(PARTITION 포함).
   → 카탈로그 정의 모달 kind select에 **PARTITION을 6번째로 추가**(orange 태그, "파티션", 엔진 동작 "파티션 컬럼 조건이 없으면 거부",
   강제식 없음). 디자인 톤 유지하며 백엔드 실 데이터를 그릴 수 있게.
3. 통과 green 카드는 스텁 — 실 lint 위반 우선(§4-6).

## 9. 결정 기록 (2026-07-25 사용자)

1. 기존 UI 전부 제거, 디자인 UI를 antd로 전면 컨버팅 (사용자 지시).
2. 로직 없는 화면 = **샘플 데이터 스텁** (사용자 확정).
3. 디자인 원본은 `docs/design/`에 커밋해 기준으로 관리 (사용자 확정).
4. 컨버팅 후 로직·정책 수립 순서는 기존 합의 유지: 규칙 데이터화 → 쿼리 상태 → 승인 → 권한 → 실행·AI (사용자 확정).
