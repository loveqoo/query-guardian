# 013 — 실행·제안 화면 (M3)

> 상태: **초안 (사용자 검토 대기)**
> 작성: 2026-07-27 · 근거: spec 012(판정하고 제안한다) · spec 008 §10 M3의 **대체**
> `.dev/plan/005-m3-execution-ui.md`는 **재작성 모델로 쓰였으므로 폐기**한다. 이 스펙이 그 자리를 잇는다.

## 0. 왜 별도 스펙인가

spec 008의 M3은 "에디터 실행 결과·**재작성** 표시"였다. 그 전제(서버가 SQL을 고친다)가
spec 008 §0에서 뒤집혔으므로, 같은 이름으로 이어 쓰면 **틀린 전제를 상속**한다.

지금 서버는 **판정하고 제안하고 원문을 실행한다.** 화면은 그것을 보여야 한다.

## 1. 지금 상태 (실측 2026-07-27)

| 항목 | 상태 |
|---|---|
| 실행·이력·감사 API를 부르는 프론트 코드 | **0개** |
| 에디터 `실행` 버튼 | 있음. 누르면 `"실행 기능은 다음 단계에서 구현됩니다"` (정직한 스텁) |
| 에디터 아래 탭 | `규칙 검사 결과` · `실행 결과` · `메시지` — 셋 다 있음 |
| `실행 결과` 탭 내용 | **디자인 샘플 그리드**("예시입니다" 문구 달림) |
| 저장된 쿼리 행 액션 | 보기 · 에디터에서 열기 · 삭제 (**실행 없음**) |
| 실행 이력 화면 | 없음. **디자인에도 없다** — 신규 |
| 캐싱 라이브러리 | 없음(`useState`만) → 불변식 F1이 성립 가능 |

**쓸 서버 API 넷** — 전부 이미 있다:

```
POST /api/lint                        판정 + 제안
POST /api/queries/{id}/execute        실행 (요청자 본인 + 승인된 것만)
GET  /api/queries/{id}/executions     그 쿼리의 실행 이력
GET  /api/executions?actor=&outcome=&before=   전체 감사 (+ 헤더 X-QG-Audit-Total)
```

## 2. 결정 (2026-07-27 사용자)

| 물음 | 결정 | 근거 |
|---|---|---|
| 조건 끼워넣기(FILTER·INTEGRITY 주입) | **M3 전에 걷어낸다** | spec 012 §7-1(P2c). 화면이 "실행된 SQL"을 보일 때 그것이 원문이어야 문구가 단순해진다 |
| 제안을 화면에서 | **클릭하면 적용** | *"쿼리 추천은 해줄 수 있어야 합니다. 코드 추천해주듯이 말이죠."* → spec 012 §7-3(P5) |
| 실행 이력 화면 | **M3에 넣는다** | 기록만 하고 볼 길이 없으면 감사가 아니라 저장이다 |
| INTEGRITY 제약 | **판정으로 옮긴다** | 주입이 유일한 강제 수단이었다(spec 012 §7-1) |

## 3. 화면 셋

### 3-1. 에디터 — 판정과 제안

**`규칙 검사 결과` 탭**이 제안의 자리다. 위반마다 조각을 붙이고, 조각에 `[적용]`을 단다.

```
⛔ users.email 은 가려서 조회해야 합니다
   email  →  mask_email(email)                    [적용]

⛔ marketing_consents 에 필수 조건이 없습니다
   WHERE + consent_yn = 'Y'                       [적용]
```

- `[적용]`은 **에디터의 SQL을 고친다.** 서버는 관여하지 않는다 — 고친 뒤 다시 판정하면
  통과해야 하고, 그것이 spec 012 §5 I3을 화면에서 확인하는 방법이다.
- 조각이 없는 위반(제안을 만들 수 없는 것)은 **문장만** 보인다. 억지로 만들지 않는다.
- 적용 후 **자동 재판정**한다. 통과하지 않으면 그 자리에서 보인다.

**`실행` 버튼**: `저장됨 && 검토 승인됨`일 때만 활성. 그 외에는 비활성 + 이유를 툴팁에
**서버 어휘 그대로**(미저장 / 검토 대기 / 반려). 화면이 새 어휘를 만들지 않는다.

**샘플 그리드는 지운다.** 이것을 먼저 지워야 "데이터가 안 와서 빈 화면"과 "샘플이라 되는 것처럼
보임"이 구분된다 — 남겨 두면 실패가 초록으로 보인다.

### 3-2. 실행 결과 — 양은 자르고, 자른 사실을 보인다

푸터는 **서버가 준 세 값을 그대로** 쓴다. 화면이 다시 계산하면 서버와 갈린다.

```
120 rows · 0.42s · LIMIT 120 적용됨
⚠ 거버넌스 상한 120으로 잘렸습니다 (요청 1000)
   더 있는지: 있음 | 없음 | 확인하지 않음
```

- "잘렸다"의 판정: **적용된 상한 == 설정 상한**일 때만. 사용자가 스스로 더 작게 걸었으면 자른 게 아니다.
- "더 있는지"는 **세 상태**다. `null`을 `false`로 좁히면 "확인하지 않음"이 "없음"으로 둔갑한다
  — 백엔드가 이 셋을 나눈 이유가 그것이다(retrospect 012가 M3에 넘긴 제약).
- 실행된 SQL 표시: **기본 접힘 토글.** P2c 이후 원문과 다른 점은 `LIMIT`과 테이블명뿐이므로,
  라벨은 "재작성 SQL"이 아니라 **"실제 실행된 SQL"**이다.
- 차단·오류는 서버의 분류 코드를 그대로 보인다. 화면이 사람 말로 번역하면 감사와 화면이 갈린다.

### 3-3. 저장된 쿼리 — 실행과 이력

- 행 액션 `실행`: **요청자 본인 + 승인됨**에서만 활성. **스튜어드에게도 비활성**이다 —
  서버가 대행 실행을 막으므로(결정 14) 활성으로 보이면 거짓 기대를 준다.
- 상세에 `실행 이력` 탭. 오류 **원문**은 서버가 스튜어드/관리자에게만 채워 준다 —
  화면은 받은 것을 그대로 보인다(없으면 코드까지).

### 3-4. 실행 이력 (신규 화면)

`거버넌스` 그룹, 스튜어드/관리자만. **디자인에 없는 화면이므로 새 관용구를 발명하지 않고**
기존 표 화면(저장된 쿼리)의 열·태그·여백을 그대로 답습한다.

열: 행위자 · 결과 · 행수 · 소요 · 상한 · 코드 · 시각 · 실행된 SQL
필터: 행위자, 결과(select) · 더 보기(커서) · 전체 건수 표시

## 4. 불변식

| # | 불변식 | 왜 |
|---|---|---|
| F1 | **결과 행은 브라우저 저장소에 남지 않는다** | spec 008 §6의 화면 쪽. `localStorage`·`sessionStorage` 전수 스캔으로 잰다 |
| F2 | 상한 세 값을 **뭉치지 않는다** | 백엔드가 나눈 이유가 화면에서 사라지면 나눈 의미가 없다 |
| F3 | 화면은 **서버 어휘를 번역하지 않는다** (차단 코드·비활성 이유) | 화면과 감사가 다른 말을 하면 대조가 안 된다 |
| F4 | `[적용]`은 **서버를 부르지 않는다** — 에디터 텍스트만 고친다 | 서버가 고치면 그것이 재작성이다 |
| F5 | 라우트를 떠나면 결과 상태를 **버린다** | F1의 정신 |

| C2 | 에디터 — 제안 `[적용]` + 실행 버튼 활성 규칙 + **샘플 그리드 제거** | U1·U2·U4 |

먼저 갖고 있어야 한다. 순서를 바꾸면 화면이 사라질 동작에 맞춰 만들어진다.

## 7. 검증

| 축 | 방법 |
|---|---|
| 기능 | E2E 8기준 |
| 기존 약속 | spec 009 스냅샷 32검사 · 백엔드 전체 스위트 |
| 디자인 충실도 | 디자인 스크린샷 대조(에디터·저장된 쿼리). **실행 이력은 기준이 없으므로 기존 표 답습** |
| 설계 품질 | `craft-reviewer` (축 분리 — 보안은 안 본다) |
| 보안·정합성 | `deep-reasoner` — 특히 **S1·S2가 fail-open을 만들지 않았는지** |
| 되돌려 실패 | 감시자마다. **되돌린 값이 정말 다른 뜻인지 먼저 확인**(retrospect 020) |
| 사람 | 사용자 실기기 확인 — 시각 작업의 1차 검증자다(retrospect 011) |

## 8. 위험

1. **S1이 과차단을 만든다.** INTEGRITY를 요구하면 지금 통과하던 쿼리가 막힌다. 데모엔 INTEGRITY
   제약이 없어 티가 안 나므로, **형태 테스트에 먼저 넣어 눈에 보이게** 한다.
2. **S2가 fail-open을 만든다.** 지우는 것이 유일한 강제 수단인 자리가 또 있는지 —
   `RewriteKind`의 남은 값들을 하나씩 대조한다. "덮여 있을 것"이라고 넘기지 않는다.
3. **실행이 실제 DB를 건드린다.** E2E가 데모 스키마·승인·검토를 요구한다.
   → 백엔드 경로를 먼저 `curl`로 확인한 뒤 UI를 붙인다(실패 원인이 앞뒤로 흐려지지 않게).
4. **픽셀 스냅샷이 새 버튼·탭으로 깨진다.** 깨지면 회귀 신호다 — 갱신 전에 **무엇이 왜 움직였는지**
   적는다. spec 009의 약속을 무르지 않는다.
5. **제안 조각이 늘면 왕복 테스트가 뒤처진다.** 조각 종류를 추가할 때 왕복이 따라오는지를
   컴파일러가 묻게 한다(`when` 망라).

## 9. 하지 않는 것

- 고쳐진 SQL 전문 생성 — spec 012 §9(조각만 준다)
- IR 트리 뷰어 — 백로그 1-a, 별도 스펙
- 소프트 삭제 포함/미포함 선택 — **요청서가 규칙을 고른다**(별도 스펙)
- spec 012 P4(죽은 마스킹 기계 삭제) — S2가 조건을 좋게 만들지만 이 스펙의 범위는 아니다
- 멀티 벤더 · 스튜어드의 타인 쿼리 삭제 정책(사용자 결정 대기)
