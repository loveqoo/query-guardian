# spec 014 — Phase 구분: 어디까지 고쳐야 무엇을 쓸 수 있는가

- **일자**: 2026-07-28 (v2 — 적대 검토 반영)
- **상태**: 초안 (사용자 검토 대기 · **L11 재결정 대기**)
- **관련**: `.dev/BACKLOG.md` 전체 · `docs/OVERVIEW.md` 4부 · `docs/adr/001`

---

## 1. 왜 이 문서인가

사용자 지적으로 시작했다.

> "이렇게 부족한 기능을 땜질하는 것처럼 보완하지 말고, phase를 구분합시다.
> **어디까지 고쳐야 어떤 기능을 쓸 수 있는지** 구분을 해야 더 좋은 피드백을 줄 수 있습니다."

지금 `.dev/BACKLOG.md`는 **결함 목록**이다. 사유와 착수 순서까지 있어서 항목 하나를 집으면
바로 일할 수 있지만, **"이걸 다 고치면 무엇이 되는가"**가 없다. 그래서:

- 무엇부터 할지가 매번 즉흥적이다 (그때그때 가장 최근에 발견된 것)
- 사용자가 우선순위 피드백을 줄 기준이 없다
- "지금 이거 남한테 보여줘도 되나"에 답할 수 없다

이 문서는 **결함을 종류로 묶지 않고, 끝났을 때 할 수 있게 되는 말로 묶는다.**

### v1이 틀린 것 (적대 검토, 2026-07-28)

이 문서 초안은 **자기가 세운 규칙을 자기 안에서 어겼다.** 기록해 둔다.

| v1의 실수 | 무엇이었나 |
|---|---|
| **L11의 전제가 틀렸다** | "백엔드에 트리 출력이 이미 있어 화면 작업만 남았다" → `toAsciiTree()`는 **Gradle 태스크로만** 노출되고 API 엔드포인트가 0건이다. 사용자에게 이 틀린 전제로 결정을 물었다 |
| **P0가 손으로 나열하다 빠뜨렸다** | 스텁 2곳을 적었는데 실측 최소 6곳. **"손 나열은 조용히 빠뜨린다"고 경고하는 문단 바로 옆에서** |
| **누락 10건** | 백로그 전수 대조에서 나옴 (아래 항목들에 반영) |
| **§5 규칙 4를 규칙과 같은 파일에서 위반** | O4가 백로그 5건 중 3건만 옮겨 2건이 유실됐다 |
| **Phase 4에 완료 조건이 없었다** | §3이 "각 Phase는 관측 가능한 완료 조건을 갖는다"고 선언해 놓고 |

## 2. 사용자 결정 (2026-07-28)

| 물음 | 결정 | 원문 |
|---|---|---|
| IR 트리 뷰어의 위치 | ~~Phase 1~~ → **Phase 3** (`O12`) | 1차 "Phase 1로 당긴다" → 사실 정정 후 재결정 **"Phase 3으로 미룬다"** |
| 감사 DB 강제·항등 마스킹의 위치 | **둘 다 Phase 1** | "Phase 1에 둘 다 넣는다" |
| 화면의 가짜 부분 | **지금 바로 표시만** | "지금 바로 표시만 붙인다" |
| CI의 위치 | ~~Phase 3~~ → **Phase 1** (`L0-d`) | "CI를 Phase 1로 당긴다" |

첫 번째는 **AI가 제시한 전제가 틀린 상태에서 한 번 결정됐다**(§1 표). 사실을 정정하고 다시 물어
뒤집혔다 — 근거는 1-A 다섯 항목이 전부 **뷰어 없이 발견됐다**는 것이다
(L1은 코드 리뷰, L2·L3은 문서 사실 검증, L12·L13은 적대 검토).
"찾는 도구가 없다"는 AI의 서술과 실제 발견 경위가 어긋났다.

## 3. Phase 정의

각 Phase는 **⑴ 끝나면 할 수 있는 말 ⑵ 항목 ⑶ 관측 가능한 완료 조건**을 갖는다.
항목의 상세(왜 아직인가·착수 순서·주의)는 `.dev/BACKLOG.md`가 보유한다.

---

### P0 — 즉시: 가짜를 가짜라고 말한다

화면 여러 곳이 **디자인 샘플 데이터**로 돌아간다. 없애거나 만드는 것은 Phase 3이고,
지금 필요한 것은 **보는 사람이 오해하지 않는 것**이다.

> 이 저장소는 이미 같은 실수를 했다 — "활성으로 보이면 거짓 기대를 준다"고 커밋 메시지에 쓰고
> 그 화면 옆에서 같은 증상을 남겼다(retrospect 021).

**목록을 손으로 적지 않는다.** v1이 둘만 적었다가 최소 넷을 더 빠뜨렸다.
대신 **탐지 신호를 정의한다**: `frontend/src/mock/design`을 참조하는 파일 집합, 그리고
"스텁"·"샘플"을 자칭하는 주석 블록. 그것이 목록의 정의다.

**완료 조건**
- 스텁 영역 목록이 **코드 한 곳의 값**으로 있다(주석이 아니라).
- **탐지 신호로 모은 집합 == 등록된 목록**을 테스트가 단정한다.
  → 목록→화면 한 방향만으로는 부족하다. **새 스텁이 생기면 실패해야** 하고,
  그러려면 화면→목록 방향이 필요하다.
- 목록의 모든 항목에 화면상 표시가 붙는다.

### Phase 1 — 통제가 진짜다

> **끝나면 말할 수 있는 것**: "등록한 제약은 실제로 강제된다."
> 여기까지가 **남에게 보여줄 수 있는 최소선**이다.

**⑴이 ⑵보다 위험하다** — 뚫리는 것보다 **거짓 확신을 주는 것**이 나쁘다.
뚫린 것은 언젠가 발견되지만, 거짓 확신은 "이미 막았다"고 믿게 만들어 아무도 안 본다.

#### 1-0. 선행 — 사람이 정해야 하는 것

| 항목 | 왜 선행인가 |
|---|---|
| **L0-a** 전역 규칙을 평가에 연결할 것인가 (L2의 전제) | 연결하면 **지금 통과하던 쿼리가 막힌다**. 강화이므로 사용자 결정 |
| **L0-b** 새 목적의 기본값을 뒤집을 것인가 (L4의 전제) | 같은 성격. 기본을 "적용"으로 바꾸면 기존 목적의 판정도 넓어진다 |
| **L0-c** 강화 축의 형태를 커버리지 표에 먼저 넣는다 | **계측이 강화보다 먼저**다. 전역 규칙 형태가 `ShapeCoverageTest`에 없으므로, 지금 켜면 새로 생기는 과차단이 **측정되지 않는다.** retrospect 020의 "완화 전 안전망 선행"의 대칭 |
| **L0-d** CI *(사용자 결정으로 Phase 3에서 당김)* | Phase 1이 세우려는 문장의 **감시자가 무인 발화를 못 하면** 그 문장이 안 선다. 1-A의 완료 조건(자동 대조)·§6의 집행 장치(⒜⒝)·구조 감시자가 **전부 이것 위에 선다.** 비용이 작고 나머지 전부를 지탱한다 |

#### 1-A. 말과 실제가 다른 것

| 항목 | 지금 |
|---|---|
| **L1** 판정 함수의 목적 인자 기본값 (`D-B`) | 호출부가 목적을 빠뜨려도 컴파일 통과 + 목적별 요건 **0건 발화** |
| **L2** 전역 스코프 규칙 (`D-M`) | 평가에서 **통째로 제외**된다. "넓게 적용"이 아니라 0회 |
| **L3** `must_be_masked` 화면 표시 (`D-L`) | 화면은 "판정 미구현", 백엔드는 **막는다** |
| **L4** 새 목적의 기본값 | 목적별 제약의 기본이 "적용 안 함" — 목적을 만들면 제약 0 |
| **L12** 규칙의 `SINGLE`/`MULTI`·`server` | 평가가 대상 테이블 참조만 본다. 더 나쁜 것 — **화면이 존재하지 않는 서버 목록(mock)을 고르게 하고**, 고른 값은 평가에 쓰이지도 않는다 |
| **L13** 실행 실패 분류 경로 무검증 | 감사 테스트가 *"실제 분류 경로는 spec 010 A7로 넘긴다"*고 적었는데 **A7은 파서 유계로 소진됐다**. 위임처가 사라진 미검증이고, `SQLTimeoutException → TIMEOUT`을 실제로 타는 테스트가 0건이다 |

L13이 여기 있는 이유: **감사가 사실을 말하는가**의 축이다. 분류가 틀리면 감사는 남는데 내용이 거짓이다.

#### 1-B. 뚫리는 것

| 항목 | 지금 |
|---|---|
| **L5** 제약 수정 경로 (`D-H`) | 등록 시 검사가 **수정**에는 없다. 요건→마스킹으로 바꾸면 요건이 사라진다 |
| **L6** 항등 마스킹 (`D-A` + 보강) | `CONCAT({col}, '')`이 전부 통과하고 감사엔 정상으로 남는다 |
| **L7** 감사 append-only (`D-D`) | 애플리케이션 관례일 뿐. DB 트리거·권한 회수 0건 |
| **L8** 사용자 규칙의 목적 유출 (`D-F②`) | 목적 밖에서도 강제식 값을 조각에 싣는다 |
| **L9** 판정 오라클 (spec 005 H4) | 남의 요청서 번호로 그 사람 기준 판정 보고서를 받는다 |
| **L10** 목적 목록 역할 게이트 (`D-I`) | 같은 컨트롤러의 다른 조회는 전부 있는데 여기만 없다 |

#### 착수 시 주의 — 순서를 틀리면 fail-open

- **L8은 방향을 틀리면 판정이 좁아진다.** 목적 필터를 판정 경로에 걸면 유출은 막히지만
  **판정까지 좁아져 fail-open**이 된다. 조각 생성에만 걸어야 한다.
- **L6은 "프로브 값에서 출력 ≠ 입력"으로 증명되지 않는다.** 프로브만 다르게 반환하는 `CASE`,
  가역 인코딩, 부분 항등 함수가 통과한다. 허용 함수 목록 또는 비가역성 계약이 필요하다.
- **L6과 O3은 같은 코드를 건드릴 수 있다.** 강제식 형태 생성기가 재작성 검증기의 마스킹 검사와
  판정 쪽 양쪽에 쓰인다 — L6이 붙일 자리가 O3이 지울 자리와 겹치는지 착수 전에 확인한다.
- **L2·L4는 1-0의 결정 없이 착수하지 않는다.**

**완료 조건**
- 항목마다 **되돌려 실패**를 확인하고, 되돌린 값이 **정말 다른 뜻인지**까지 확인한다.
- 그것으로 부족하다 — 새로 만든 감시자마다 **KDoc이 약속한 범위의 경계 밖에도 심어** 본다
  (retrospect 018: 되돌려 실패는 감시자의 *존재*만 잰다).
- 1-A는 추가로 **화면·백엔드가 같은 어휘를 쓰는지 자동 대조**가 있어야 한다.
  `must_be_masked`가 갈라진 이유가 프론트 상수와 백엔드 정의가 별개였기 때문이다.
  → 기존 `.dev/tools/wire-contract-check.py`에 어휘 쌍을 추가하는 것이 가장 싸다.
- 감사 삭제가 **DB 권한으로** 거부되는 것을 통합 테스트가 확인한다.
- L13: `SQLTimeoutException`·`SQLException`을 실제로 던져 감사 코드가 나오는 것을 확인한다
  (지금은 스파이가 분류 결과를 직접 던져서 분류기를 안 탄다).

### Phase 2 — 사람들이 우회하지 않는다

> **끝나면 말할 수 있는 것**: "실제 팀에 붙여도 딴 길로 새지 않는다."
> 거버넌스 도구가 버려지는 이유는 대부분 뚫려서가 아니라 **일을 못 하게 해서**다.

| 항목 | 지금 |
|---|---|
| **U1** 겹 잇기 (spec 011 Q3) | 과차단 3건(`F2`·`H6`·`K4`) 전부 겹 경계. **읽기 좋게 쪼개면 막히고 뭉치면 통과** |
| **U2** 요청서가 규칙을 고른다 | 정당한 예외를 표현할 길이 없다(복구 작업이 그냥 막힌다) |
| **U3** 조각이 스코프를 나른다 (`D-G`) | CTE·파생·UNION 팔 안의 위반에는 조각 없이 문장만 나간다 |
| **U4** 형태 커버리지 표를 넓힌다 | X2(멀티 벤더)의 안전망이 되려면 지금 표가 커버 못 하는 축을 채워야 한다. U1은 과차단 *제거*이지 형태 *추가*가 아니다 |

#### 착수 시 주의

- **U1·U2는 완화다.** 이 저장소에서 완화는 fail-open을 만든 적이 있다(retrospect 010).
  spec 011의 원칙 셋을 그대로 적용한다 — 사실은 넓히되 기준은 좁힌다 /
  완화마다 **악용 형태를 먼저** 쓴다 / 확신 없으면 완화하지 않는다.
- **U2는 "면제"가 아니라 "선택"이다.** 요청서에 적히고, 승인자가 보고, 감사에 남는다.
  안전은 셋에서 온다: 기본은 엄격한 쪽 / 고를 수 있는 건 등록된 것만 / 고른 사실이 승인 대상.
- **U3는 적용기가 파서가 된다는 뜻**이다. 별도 결정이 필요하다.
- **L2(강화)와 U1(완화)이 같은 형태를 건드린다** — `K4`는 사용자 규칙 축의 겹 경계다.
  L2가 전역 사용자 규칙을 켜면 그 계열이 늘어난다. 순서상 L2가 먼저이므로 U1은 늘어난 뒤의 집합을 본다.

**완료 조건**
- `ShapeCoverageTest`의 `KNOWN_OVERBLOCK`이 **공집합**이 된다(집합 동등성을 이미 단정하고 있다).
- 완화마다 **반대편을 잰다** — `BypassSuiteTest`가 여전히 초록인지.
- U3까지 하면 `FixRoundTripTest`의 `noFixExpected` 항목이 실제 조각으로 바뀐다
  (그 테스트가 "안 줄 자리에 줬다"를 실제로 실패시킨다).

### Phase 3 — 나 없이 돌아간다

> **끝나면 말할 수 있는 것**: "담당자가 화면에서 다 하고, CI가 지킨다."

| 항목 | 지금 |
|---|---|
| ~~**O1** CI~~ | **Phase 1로 옮김**(L0-d) — 사용자 결정 |
| **O2** 매핑 UI | 논리→물리 매핑을 화면에서 못 만든다. 정합성 제약·변경 감사도 없다 |
| **O12** IR 트리 뷰어 | 에디터 옆에서 IR과 **누락 노드**를 본다. 판정 사각의 조기 발견 창구. **백엔드 API + DTO가 선행**이고(현재 트리 출력은 Gradle 태스크뿐, IR을 주는 API 0건), 그 엔드포인트는 판정 근거를 그대로 노출하므로 **역할 게이트 설계까지 필요**하다(L9·L10과 같은 오라클 축) |
| **O3** 죽은 마스킹 코드 (spec 012 P4) | 동작은 없는데 코드가 남았다. 테스트 일곱이 그것을 **재료로** 쓴다 |
| **O4** 화면 사본 (`D-J` **5건 전부**) | 실행 이벤트 표 2벌(이미 갈라짐) · `FixDto.kind`가 String(같은 파일의 다른 것은 enum) · `src/api/`에 전송과 판단 혼재 · `MoreRows`가 한국어 표시 문구를 타입으로 굳힘 · 진입 파일의 스텁 |
| **O5** 미결 정책 둘 | 담당자가 남의 쿼리를 지울 수 있는가 / 오류 원문을 누구까지 보는가 |
| **O6** 측정 안 된 가드 | 다중 인스턴스 `USING` |
| **O6'** **없는** 2선 기대치 (`D-F①`) | 재작성 검증기가 계획만 순회해 "물리 테이블 집합 == 허용 매핑 집합" **동등성을 단정하지 않는다.** 측정이 부족한 게 아니라 **기대치 자체가 없다** — O6과 성격이 다르다 |
| **O7** 거짓말하는 주석 (`D-K`) | 마일스톤 언급 주석에 회수 절차가 없다. **그리고 근거를 잃은 주석도 같은 유형**이다 — 스키마의 컬럼 폭 사유가 "재작성 SQL은 원본보다 커지므로"인데 spec 012가 그 전제를 없앴다 |
| **O8** 가짜 화면 | P0에서 표시만 붙였다. 여기서 실제로 만들거나 제거한다 |
| **O9** 백엔드 DTO 사본 | 실행 이벤트 매핑 12필드가 두 컨트롤러에 복제. **원문 마스킹 정책이 그 사본 하나에만 있다** — O5를 닫는 수단이다 |
| **O10** 도달 불가 방어선의 처분 | spec 012 P2b가 근거를 없앤 장치들. 남긴다면 "도달 불가이며 왜 남기는가"가 코드에 있어야 한다 |
| **O11** 스펙이 구현을 서술한다 (`R4`) | spec 008이 493 → **611줄**로 오히려 늘었다. §5-4가 중복 금지를 규칙으로 세운 마당에 원인 스펙은 그대로다 |

#### 착수 시 주의

- **O1이 먼저다.** 지금 "컴파일러로 올릴 수 있는 것은 전부 올렸다"는 말이 **CI 부재를 전제로** 쓰여 있다.
- **O3은 한 번 착수했다가 되돌린 이력이 있다.** 순서가 정해져 있다 —
  ⑴ 테스트 일곱의 재료를 주입/상한으로 바꿔 초록 유지 ⑵ 그 뒤에 지운다 ⑶ 되돌려 실패로 확인.
- **O5는 코드 작업이 아니라 사람의 결정**이다. 현행이 테스트로 고정돼 있다.

**완료 조건**
- 푸시마다 백엔드·프론트 테스트가 돈다.
- 카탈로그·매핑을 **화면만으로** 처음부터 구성할 수 있다 — E2E 시나리오 하나가 그것을 밟는다.
- O5: `ExecutionFlowIntegrationTest`의 현행 고정 테스트가 **결정에 맞게 바뀐다.**
  (백로그 항목 수를 조건으로 삼지 않는다 — 지워서 충족되는 기준은 굿하트다.)
- O8: P0에서 만든 스텁 목록이 **공집합**이 된다.

### Phase 4 — 넓힌다

> **끝나면 말할 수 있는 것**: "MySQL만이 아니고, 사람만 쓰는 것도 아니다."

| 항목 | 비고 |
|---|---|
| **X1** API 진입점 + AI 에이전트 | 판정 결과가 이미 구조화돼 있다. 지금 진입점은 브라우저뿐 |
| **X2** 멀티 벤더 (PostgreSQL·Trino) | **ADR 001이 IR 재검토의 전환점으로 지목한 지점** |
| **X3** 컬럼 수준 카탈로그 검증 | 판정 축 추가 → 별도 스펙 |

#### 착수 시 주의

- **X2는 착수 전에 ADR 001을 다시 연다.** "직접 만든 IR을 유지한다"는 결정이
  **재검토 예약과 함께** 내려졌고, 그 조건이 정확히 멀티 벤더다.
  잃는 것도 계산에 넣는다 — **관계대수로 가면 `no-select-star`를 표현할 수 없다**
  (별이 컬럼 목록으로 펼쳐져 "별을 썼다"는 사실이 사라진다).
- **X1·X2는 캐싱을 부른다.** 파싱 결과의 구조와 실행 핸들이 같은 파싱에서 나왔다는 것을
  타입이 보장하지 못한다. 오늘은 생성 지점이 하나뿐이라 위험이 낮지만,
  **캐싱 계층이 생기는 순간 판정↔실행 분기 위협이 다시 열린다.** 착수 전에 그 짝을 타입으로 묶는다.
- **X1은 Phase 1이 끝나야 의미가 있다.** 에이전트에게 게이트를 주는 것의 값은
  게이트가 진짜일 때만 나온다.

**완료 조건**
- X1: 브라우저 없이 판정→승인→실행 전 과정을 태우는 통합 테스트가 있다.
  게이트를 우회하는 경로가 없음을 구조 감시자가 확인한다(실행기 접근 규칙의 확장).
- X2: 새 방언에서 형태 커버리지 표가 초록이 된다. 방언마다 **문법 전수 대조**를 다시 하고
  그 결과가 표에 형태로 들어간다.
- X3: 별도 스펙으로 분리한다 — 여기서는 완료 조건을 정하지 않는다.

## 4. 왜 이 순서인가

| 순서 | 근거 |
|---|---|
| **1 → 2** | Phase 2는 대부분 **완화**다. 통제가 진짜인지 모르는 상태에서 완화하면 **무엇이 넓어졌는지 잴 기준이 없다.** 이 저장소는 오차단 완화가 fail-open을 만든 실측 이력이 있다 |
| **2 → 3** | 운영 이관은 **쓸 만한 것**을 넘기는 것이다. 과차단이 남아 있으면 담당자가 예외 요청을 계속 손으로 받는다 — 넘긴 것이 일이지 도구가 아니다 |
| **3 → 4** | 방언이 늘면 문법 전수 대조를 방언마다 다시 해야 한다. CI 없이 그것을 하면 회귀를 사람이 지킨다 |
| **P0는 어디든 앞** | 비용이 거의 0이고, 안 하면 그 사이 보는 사람마다 오해한다 |

## 5. Phase를 건너는 의존 — 알고 있어야 할 것

이 순서에는 **뒤 Phase가 앞 Phase의 완료 조건을 지탱하는 자리**가 있다. 정직하게 적는다.

1. ~~**Phase 1의 완료 조건은 Phase 3에 의존한다**~~ **해소** — 사용자 결정으로 CI를 `L0-d`로 당겼다.
   그 전에는 1-A가 요구하는 "자동 대조"가 *"누가 테스트를 돌릴 때만"* 발화해서,
   Phase 1이 세우려는 문장의 감시자가 무인 발화를 못 했다.
2. **L2·L4(강화)는 계측이 선행이다** — 1-0-c. 지금 켜면 새 과차단이 측정되지 않는다.
3. **X2의 안전망은 아직 없다.** v1은 "표가 Phase 2에서 넓어진 뒤"라고 썼는데
   Phase 2에 표를 넓히는 항목이 없었다. U4로 세웠다.
4. **L6(Phase 1)과 O3(Phase 3)이 같은 코드를 건드릴 수 있다.**

## 6. 이 문서를 낡지 않게 유지하는 규칙 — 그리고 그 집행

이 문서는 **옮겨 쓰이는 원본**이 된다.
(2026-07-28에 `docs/OVERVIEW.md` 초안이 낡은 인덱스를 옮겨 숫자 넷을 틀렸다 — 그 재발 방지다.)

1. **항목이 해결되면 그 자리에서 지우거나 취소선을 긋는다.**
2. **숫자는 세어서 나온 값만 적고, 인용할 때마다 다시 센다.**
3. **Phase가 끝나면 그 절을 요약 한 줄로 줄인다.**
4. **`.dev/BACKLOG.md`와 중복하지 않는다.** 여기는 "무엇을 쓸 수 있게 되는가",
   거기는 "왜 아직인가·어떻게 착수하는가".

### 집행 — 지금은 사람뿐이다

**위 넷에 자동 집행자가 0이다.** CI 없음, 훅 없음, `docs/`·`.dev/`를 읽는 테스트 0건.
그래서 규칙을 어겼을 때 알려 주는 주체는 사람이고, **그 사람이 바로 규칙을 어긴 사람**이다.
이 문서는 그것을 "규칙"이라 부르지만 **집행이 붙기 전까지는 다짐**이다.

v1이 규칙 4를 규칙과 같은 파일에서 어긴 것이 증거다(O4가 5건 중 3건만 옮겨 2건 유실).

**붙일 수 있는 장치 둘** (O1이 생기면 자동으로 돈다):

- **⒜ 토큰 대조**: 백로그의 `D-[A-Z]` 토큰 집합 ⊆ 이 문서가 인용한 토큰 집합.
  백로그에 새 항목을 추가하면 여기를 고치기 전까지 빨간불. 취소선 그어진 것은 자동 제외.
- **⒝ 스텁 대조**: P0의 스텁 목록 == `mock/design`을 참조하는 파일 집합.

**⒜·⒝를 언제 만드는가**: ⒝는 P0의 완료 조건에 이미 들어 있다. ⒜는 이 문서가 살아 있는 한
계속 필요하므로 **Phase 1 착수와 함께** 만든다 — 집행 없는 규칙은 반드시 낡는다.
그리고 **`L0-d`(CI)가 Phase 1로 들어왔으므로 이 둘은 만들어지는 즉시 무인으로 돈다.**
위 문단의 "지금은 사람뿐"은 **Phase 1 착수 전까지의 서술**이다.

## 7. 비목표

- **일정 추정을 하지 않는다.** 항목 수는 난이도와 무관하다(L10은 한 줄, L6은 설계가 필요하다).
- **Phase 안의 순서를 고정하지 않는다.** 1-0 → 1-A → 1-B의 순서와 각 항목의 fail-open 주의만 고정한다.
- **Phase를 건너뛰는 것을 금지하지 않는다.** 다만 건너뛰면 **그 Phase의 문장을 말할 수 없다**는 것이
  이 문서의 전부다.
